**目的**：回答"平地模型（`m20_piper_flat_20260930`）是否达到部署水平"，并用同一套
harness 对照多地形模型（`m20_piper_rough_20261002`）。

**方法**：三层

## 4. 单命令阶跃（8 s 命令 / 后 6 s 稳态）

| 命令 | 平地 实测（跟踪度） | 多地形 实测（跟踪度） |
|---|---|---|
| `vx +0.5` | 0.520（104%） | 0.583（117%） |
| `vx −0.5` | −0.352（70%） | −0.401（80%） |
| `vy +0.5` | 0.583（117%） | **0.046（9%）** |
| `vy −0.5` | −0.437（87%） | −0.555（111%） |
| `wz +0.5` | 0.378（76%） | 0.440（88%） |
| `wz −0.5` | **−0.027（5%）** | −0.288（58%） |

### 4.1 发现：侧移/转向存在**方向性不对称**（需训练侧确认）

* 平地模型：`wz −0.5` 只跟 5%，而 `wz +0.5` 跟 76%；
* 多地形模型：`vy +0.5` 只跟 9%，而 `vy −0.5` 跟 111%；
* 隔离单发（只跑那一个阶段、10 s）复现同样结果 ⇒ **不是顺序/残留效应**；
* 两个模型"坏的方向"还不一样（一个坏左转、一个坏左移）⇒ 更像
  **左右侧轮子符号/增益**或训练侧 `yaw_rate`/`base_velocity` 符号约定的问题，
  而不是某个模型的偶然。

> 建议（训练侧）：用同一套 MJCF 跑 `vy/wz = ±0.3/±0.7` 的左右对称性探针，
> 输出"命令 vs 实测"四象限表。**这条不查清，就不能说部署包线已经验证。**

### 4.2 发现：侧移响应有 2~4 s 建立时间

同一条 `vy 0.2`，4 s 窗口（稳态窗 2.4 s）测出 ≈0，8 s 窗口测出 0.58 ⇒
验收判据必须**固定窗口长度**，否则会把"慢"误判成"不跟"。

## 5. 过程中顺手发现/修掉的问题

| # | 问题 | 处理 |

## 7. 复现（宿主机一行式）

```bash
# 0) 前置
docker start m20_piper_ros && DISPLAY=:1 xhost +local:

# 1) 命令组合扫描（平地 = 默认；多地形用 M20_POLICY_DIR 绝对路径）
docker exec -it m20_piper_ros bash -lc 'cd /root/m20_piper_ws && source /opt/ros/humble/setup.bash && source install/setup.bash && exec python3 tests/command_sweep.py --repeat 3'

docker exec -it m20_piper_ros bash -lc 'cd /root/m20_piper_ws && source /opt/ros/humble/setup.bash && source install/setup.bash && export M20_POLICY_DIR=/root/m20_piper_ws/src/M20_sdk_deploy/policy/m20_piper_rough_20261002 && exec python3 tests/command_sweep.py --repeat 3'

# 2) 完整验收（含 command_sweep；SWEEP=0 跳过它）
docker exec -it m20_piper_ros bash -lc 'cd /root/m20_piper_ws && source /opt/ros/humble/setup.bash && source install/setup.bash && exec env SKIP_BUILD=1 bash tests/run_all.sh'
```
