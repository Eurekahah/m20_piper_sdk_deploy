# （模板）缺陷 / 特性记录条目

> 用途：`docs/review/DEFECT_LOG_zh.md` 里**每条**记录都按这个骨架写，
> 一条记录 = 一个"可回溯的事件"，方便日后查"当时为什么这么改"。
>
> 复制下面 `### DEF-0xx ...` 整段追加到 DEFECT_LOG 的"记录"区（新条目放最上面）。
>
> 部署仓库比训练仓库多两栏：**影响面**里必须写清"仿真 / 真机 / 二者"，
> **结果**里必须写清"跑了哪条测试命令、退出码/数值是什么"。

---

### DEF-0xx `<一句话标题：现象 + 影响面>`

| 项 | 内容 |
|---|---|
| 日期 | `YYYY-MM-DD` |
| 类型 | `缺陷` / `特性` / `重构` / `文档` |
| 状态 | `已修` / `部分已修` / `未修（见 TODO_zh.md P?）` |
| 影响面 | `sim2sim` / `sim2real` / `二者` |
| 关联 | `<分支> @ <commit>`；`<文件:符号名>`；相关条目 `DEF-0yy` |

**1. 现象（怎么发现的）**

* 触发条件 / 复现命令：
* 可观测证据（报错原文、实测数字、日志片段）：
* 影响面（哪些状态机状态 / 哪些策略 / 哪些节点受影响）：

**2. 根因**

* 定位过程（做过哪些排除实验、A/B 了哪些开关）：
* 真正的原因（文件:符号名 + 一句话机制）：
* 为什么以前没暴露 / 什么时候开始暴露：

**3. 修正**

* 改了什么（文件:符号名 + 一句话）：
* 为什么这么改（备选方案是什么、为什么否掉）：
* 兼容性代价（要不要换策略 / 旧 policy 还能不能用 / 真机侧要不要同步改）：

**4. 结果（验收）**

* 实测数据（**数字 + 复现命令**；对照组要写清差异）：
* 回归检查（跑了哪些测试、退出码、是否覆盖了 sim2sim 端到端）：
* 遗留问题 / 未覆盖的场景：

---

## 写这条记录时的检查清单（写完删掉）

1. 现象里有没有**原始报错/原始数字**？（不要只写"效果不好"）
2. 根因是不是"可证伪"的？（有没有对照实验或独立复算支持）
3. 结果里有没有**改动前后的对比数字**？
4. 有没有写"这条修正的反面代价"（换策略 / 分布变化 / 真机侧要跟着改）？
5. 关联里有没有 commit hash（方便 `git show`）？
6. 如果这条修正引入了环境变量或新话题，**有没有写进 `README.md` / `WORKFLOW_zh.md`
   的开关登记表**？
