# 开发、测试与代码质量

**职责**：规定分支、测试、合并门槛、调试和文档维护方式，并汇总当前代码质量缺口。
当前任务优先级只看 [`STATUS_zh.md`](STATUS_zh.md)。

## 1. 基本约束

`main` 必须始终满足：

1. 能编译。
2. L1 策略接口检查通过。
3. 仿真端到端冒烟通过，且实时因子接近 1.0。

未达到以上条件的实验只能留在功能分支或 `wip/` 分支。

分支命名：

| 类型 | 用途 |
|---|---|
| `feat/<topic>` | 新功能 |
| `fix/<topic>` | 缺陷修复 |
| `docs/<topic>` | 文档 |
| `wip/<topic>` | 调试现场，不合并 |

提交使用 conventional commit 前缀，并在正文写明“为什么、验证命令、关键数字、
关联 DEF 编号”。接口类改动必须写清改前和改后。

## 2. 模块与最低测试

| 模块 | 最低测试 |
|---|---|
| 策略布局、动作映射、history | L1 + L3 |
| 状态机、安全接管、急停 | L0 + L3 |
| 腿部接口、标定 | L3 + 真机 L4 |
| MuJoCo 模型和执行器 | L3 + L3' |
| 机械臂 IK、键盘遥操 | L2 + L3 |
| 真臂 adapter | L2 + 真机 L4 |
| VR | L2 + L3 + 真机 L4 |
| 文档和脚本 | 编译不回归 + 脚本自检 |

## 3. 测试层次

| 层 | 内容 |
|---|---|
| L0 | `colcon build` |
| L1 | `check_policy_interface.py` |
| L2 | 单节点话题回环，如 `arm_real_bridge_check.py` |
| L3 | sim2sim 端到端 |
| L3' | `check_mjcf_contract.py` |
| L4 | 真机，必须有人值守并准备急停 |

常用命令：

```bash
# 完整仿真验收
bash tests/run_all.sh

# 跳过编译
SKIP_BUILD=1 bash tests/run_all.sh

# 只跑指定模式
SKIP_BUILD=1 MODES='hold rl' bash tests/run_all.sh

# 进入 RL 的失败率
python3 tests/sim2sim_smoke.py --mode rl --duration 20 --repeat 12

# 22 阶段命令扫描
python3 tests/command_sweep.py --repeat 3

# VR 机械臂链路
python3 tests/vr_arm_chain_check.py --out /tmp/m20_vr_arm_check
```

### 3.1 仿真判据

- 高度：
  `root_z - mean(4 wheel z) + 0.09`。
- 倾角：`acos(-g_z)`。
- 摔倒/接管：倾角 > 0.8 rad 或高度 < 0.30 m。
- 测试期间实时因子必须接近 1.0；电池降频时结果不可信。

### 3.2 当前测试口径问题

在修复前，需要注意：

- `tests/sim2sim_smoke.py` 把初始位姿、idle 和站立档固定为旧训练姿态流程，
  与产品默认的厂商站立流程不同。
- `tests/run_all.sh` 对 `arm` 仍使用单次 0 失败判据，而 `arm` 同样进入 RL，
  会受入口瞬态影响。
- 测试运行前没有统一强制清理残留节点和断言发布者唯一性。

以上三项都属于当前待办，不应靠文档说明绕过。

## 4. 合并门槛

合并前逐项确认：

1. 提交职责单一，提交信息包含验证结果。
2. L0、L1、相关 L2/L3 通过。
3. 换策略时同时提交 ONNX、TorchScript 和 layout。
4. 真机行为、接口、坐标或增益变化已记录到契约或缺陷历史。
5. 测试数字写入 `STATUS_zh.md` 或 `DEFECTS_zh.md`。
6. 新环境变量有默认值、用途和所属模块说明。
7. 不把临时打印和默认开启的实验开关合入。
8. 使用 `git merge --no-ff` 保留分支形状。

## 5. 调试约定

临时诊断优先使用环境变量，默认保持关闭。不要直接改默认控制路径。

查看当前环境变量入口：

```bash
rg -n 'getenv\("M20_|os\.environ|getenv\(' src/M20_sdk_deploy -g '*.{h,hpp,cpp,py}'
```

查看已有测试和脚本：

```bash
rg --files tests src/M20_sdk_deploy/scripts | sort
```

打印统一使用模块前缀，例如 `[STANDUP]`、`[RL]`、`[ARM]`。高频打印必须限频或默认关闭。

排查策略问题时按以下顺序：

1. 编译模式是否正确。
2. 策略目录和 layout 是否正确。
3. 关节顺序、坐标系、默认角、增益是否一致。
4. 开环固定动作是否正确。
5. 零动作是否稳定。
6. 接策略零速度命令是否稳定。
7. 最后逐个放开机械臂、速度和机身姿态命令。

不要跳过接口检查直接调策略参数。

## 6. 当前代码质量缺口

以下问题不一定阻塞仿真演示，但上真机前应逐步解决：

### 6.1 安全层

`SafeController::Run()` 目前实际只执行驱动、关节 NaN、温度和 IMU NaN 检查。

- `IsBatteryNormal()` 和 `IsUserCommandNormal()` 已定义但未调用。
- 关节/IMU 更新超时标志尚未完整实现。
- `current_time_` 使用秒，而命令心跳阈值使用 `1000.0`。
- `safe_control_mode` 注释的“模式”和实际“错误码”语义不一致。

### 6.2 限位和状态机

- `liedown_state.hpp` 的 `LimitNumber()` 返回值被丢弃，趴下膝目标可能超出关节上限。
- `arm` 测试判据与入口瞬态不一致。
- 厂商站立和训练 RL 默认姿态尚未由训练侧统一。

### 6.3 常量重复

默认关节姿态、末端默认位姿、增益和限幅在 C++/Python 多处重复。
建议后续抽取机器可读合同文件，并由测试生成或校验。

### 6.4 路径和安装

- `M20_POLICY_DIR` 按进程 cwd 解析，默认目录按源码文件位置解析。
- 安装后从源码树外启动时，策略目录可能无法解析。
- 短期要求环境变量一律使用绝对路径。

### 6.5 死代码与构建

- 旧 `M20PolicyRunner`、旧键盘仿真接口、无人使用的 `car_move` 等仍在仓库中。
- `main.cpp` 引用了仓库不存在的 `backward.hpp` 死分支。
- CMake 使用 `-w` 关闭全部警告，掩盖真实问题。

### 6.6 并发

`UserCommand` 被键盘、VR、策略和安全线程共同读写。当前只对部分字段加锁，
需要明确字段所有权，或改为原子/双缓冲。

### 6.7 测试覆盖

- 默认产品流程与测试默认流程不一致。
- 纯函数缺少单元测试。
- 真机侧只有预检和话题级桥接测试，没有可重复的 L4 验收脚本。
- 注释和 TODO 仍可能引用已合并或删除的旧文档；以本索引为准。

## 7. 文档维护

长期文档只保留以下入口：

| 文档 | 只写什么 |
|---|---|
| `README_zh.md` | 导航和阅读路径 |
| `STATUS_zh.md` | 当前状态、验收摘要、唯一待办清单 |
| `DEPLOY_zh.md` | 怎样部署和运行 |
| `CONTRACT_zh.md` | 接口、参数、仿真/真机差异 |
| `DEFECTS_zh.md` | 历史现象、根因、修复和实测证据 |

规则：

1. 不再按日期新建 `DONE`、`TODO`、`ACCEPTANCE` 文档。
2. 已完成且仍有架构价值的工作写进状态摘要；完整故障链写进缺陷历史。
3. 临时实验不新建长期文档，直接写入对应缺陷条目。
4. 文档中的命令必须可复制，路径必须可解析。
5. 修改接口时同时更新合同和测试。
