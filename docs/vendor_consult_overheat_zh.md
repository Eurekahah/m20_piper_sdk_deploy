## 给厂商的正文（复制这一段）

**主题：M20 + Piper 在"站立保持"工况下前腿侧摆/膝关节持续升温至 100 ℃，想请教电机连续能力与控制方式**

**1. 背景**

* 机型：M20（轮式）+ AgileX Piper 臂与夹爪。机器人主机侧运行我们基于贵司 M20 SDK
  （`M20_sdk_deploy`，仓库 commit `<填写：git rev-parse HEAD>`）编译的部署程序；
  贵司机器人服务/固件版本：`<填写>`。
* 工况：进入 SDK 模式后执行**站立状态机（`z` 起立）并保持在站立姿态**（不进 RL 策略）。
  机器人静止不动、平地、无外加负载。

**2. 现象**

* 站立数十秒~数分钟后，**前腿的侧摆（hipx）与膝关节**持续升温：我们的部署程序里保护阈值是
  `>100 ℃`（`safe_controller.hpp`），到 100 ℃ 触发安全接管 → 切 joint damping（卸力）→ 趴下；
  卸力后约 10 s 温度掉回阈值以下，保护自动解除、可再站起来。
* **热机状态下 65 s 内出现 3 次"过温 → 趴下 → 恢复"循环**；冷机起约 4.4 min 一次。
* 过温的**始终是前腿的 hipx + knee**（后腿同名义关节低 20~40 ℃，hipy 与轮子完全不热）；
  具体哪一个先跨 100 ℃ 不固定（我们见过右前膝先跳，也见过左前侧摆先跳）。
* **电机 100 ℃ 时 `driver_temp` 只有 53~64 ℃** ⇒ 发热在电机绕组侧，不是驱动器功率级。

**3. 我们测到的数据**

`/JOINTS_DATA` 的 `torque` / `motion_temp`（200 Hz 录制，取稳态窗口均值）：

| 工况 | 腿 kp/kd | 前腿 `hipx` τ | 前腿 `knee` τ | 12 关节 Σ\|τ\| | Στ²（∝发热） | 温度表现 |
|---|---|---|---|---|---|---|
| 贵司机器人**内置控制器**站立（不跑 SDK） | 未知 | +9.8 / −9.6 N·m | −9.9 / −10.6 N·m | 61.7 N·m | 554 | **平：整机 27.6~48.5 ℃，各关节 +0.5~0.6 ℃/min** |
| 我们 SDK 站立（目标 = 训练默认姿态，kp=200/kd=4） | 200 / 4 | **+29.0 / −29.3** | **−22.1 / −25.6** | 228.8 N·m | 5244 | 65 s 内 3 次过温 |
| 我们 SDK 站立（改用贵司**原版两段式轨迹**：蹲 0.12 m → 升到 0.48 m） | 200 / 4 | +10.7 / −12.2 | −16.1 / −18.9 | 143.5 N·m | 1850 | 约 4.4 min 过温 |

两点补充：

* **同一台机器人、同一地点，贵司内置控制器站立时这些关节只有约 10 N·m、温度完全不涨**；
  而用 SDK 站立（无论贵司原版两段式轨迹还是我们的目标姿态）都会过热。
* 用 `τ = kp ×（目标角 − 实测角）` 反推，我们在 12 个腿关节上都能逐一对上
  （kp=200，误差 <0.01 N·m）⇒ 实测 `torque` 就是电机实际出力。

**4. 我们已经排除的（供参考，避免重复排查）**

* **不是抖动/振荡**：稳态保持段 position 标准差 0.0000 rad、速度标准差约 0.011 rad/s、
  力矩标准差 0.02~0.05 N·m（纯静载）。
* **不是饱和/限幅**：最大力矩 29 N·m，远低于 76.4 N·m。
* **不是标定/顺序/符号错误**：力矩与"kp × 角度偏差"逐关节吻合，方向与标定表自洽。
* **不是驱动器问题**：`motion_temp` 远高于 `driver_temp`（绕组铜损主导）。
* 相关性已定位：当前站立目标离机器人**自然平衡姿态**越远，静力矩越大。
  把目标挪到贵司两段式轨迹（更接近自然姿态）后，侧摆从 29 N·m 降到 10.7 N·m、
  过温时间延长约一个数量级 —— 但 knees 仍有 16~19 N·m，最终仍会过热。

**5. 想请教贵司的问题（本次咨询重点）**

1. **电机型号与连续能力**：M20 的 `hipx`（侧摆）与 `hipy`/`knee` 是否**同一型号电机与减速比**？
   各自的**连续（额定）力矩 / 额定电流 / 允许持续工作时间**、绕组**绝缘等级**与
   **允许最高绕组温度**是多少？SDK 里的腿 `effort_limit = 76.4 N·m` 是峰值还是连续能力？
2. **"静态保持"是否在设计工况内**：靠 PD 持续顶住一个姿态、近似堵转几分钟到十几分钟，
   电机的设计连续能力大概在什么力矩范围？我们能长期保持的最大力矩是多少？
3. **贵司内置控制器的做法**：不跑 SDK、用贵司内置控制器站立时，这些关节只有约 10 N·m 且不升温。
   它用的**目标姿态 / 刚度阻尼 / 是否带重力补偿**分别是多少？
   我们能否直接调用这种"低发热站立/待机"模式，或请您给出它站立时的目标关节角？
4. **`hipx` 限幅的历史**：`ee86b46`（2026-08-12）把 `hipx` 的限幅从 `32.4 N·m / 45 rad/s`
   改成 `76.4 N·m / 22.4 rad/s`（与 hipy/knee 对齐）。原版按"更小力矩、更快转速"设定，
   是否说明侧摆关节是**偏小/偏快**的型号？改成 76.4 后**连续**力矩能力是否也随之变化？
5. **保护阈值**：我们代码里的 `>100 ℃` 接管阈值是否偏保守/偏激进？贵司固件的过温阈值是多少？
6. **建议的站立姿态**：贵司是否有"长时间站立推荐的目标姿态/站高"（让 hipx/knee 静力矩最小）？
   我们愿意按贵司推荐值调整站立目标。

**6. 我们这边的计划（若贵司暂时无法提供数据）**

* 先把站立档刚度从 SDK 原版的 `kp=200 / kd=4` 降到 40~80，并/或把站立目标姿态挪到
  "静力矩最小"的位置；用同样的 62 s 录制对比 Στ² 与温升速率
  （目标：向贵司内置控制器的 Στ²=554、+0.6 ℃/min 靠近）。
* 若贵司确认该工况已超出电机连续能力，我们再从"缩短站桩保持时间 / 改站姿 / 换电机"里选路。
